# Track Detail Results Redesign

## Goal

赛道详情页从“运行记录中心”调整为“模型结果中心”：用户优先看到该赛道上哪些模型已有有效评测结果、排名如何、能力维度表现如何，以及可查看哪些样本预测结果。运行列表保留，但默认弱化隐藏。

## Scope

- “该赛道的运行”列表默认折叠。
- “启动运行”卡片提供显示/隐藏历史运行按钮。
- 模型选择提示改为三态：
  - `已评测`：该模型在此赛道最近一次相关终态评测单元成功。
  - `运行未成功`：该模型最近一次相关终态评测单元存在失败样本或失败状态，可进入对应运行重跑失败样本。
  - `未评测`：没有相关终态评测单元。
- 模型选择不再展示 `已加载/未加载/加载中`，因为当前策略是每次运行重新加载模型。
- 赛道详情页排名卡片去掉策略选择，固定使用 `latest_valid_result`，并移除同卡片内的重复榜单图表。
- 报告页中的能力雷达图能力迁移到赛道详情页，数据来自赛道上每个模型的最近有效成功结果。
- 赛道详情页底部新增样本列表，按赛道级最近有效成功结果聚合不同模型运行。
- 新增模型比较入口：选择两个模型，按测试用例集/能力维度展示主指标，较优值高亮；暂不计算总分。

## Backend Design

新增 `GET /tracks/{track_id}/results`，返回赛道级结果摘要。后端按模型选择最近相关结果：

- `model_statuses` 基于该模型在赛道内最近终态 unit 判断三态。
- `model_metrics` 和 `capability_metrics` 只取最近成功 unit，避免失败样本进入榜单和结果聚合。
- `sample_forecast_links` 基于最近成功 unit 的 sample metric 聚合，默认按 `track.primary_metric_id` 作为主指标，可分页、按能力块筛选、按模型筛选、按样本顺序或指标排序。

样本列表的 `run_id` 使用该样本聚合行中最近一条成功 metric 所属运行，作为进入现有样本详情页的代表运行。跨运行同样本全模型详情后续单独设计。

## Frontend Design

`TrackPage.vue` 作为赛道详情聚合视图：

- 加载 `getTrackResults(trackId, sample query)`。
- “启动运行”卡片控制历史运行列表展开状态。
- `TrackRunPanel` 接收模型三态，渲染为短提示和可选运行链接。
- 排名卡片只展示 metric 选择和 `RankingTable`。
- 能力雷达图复用 `CapabilityProfile`，传入赛道级 `ReportDTO` 形状数据。
- 样本列表复用可抽出的样本表组件，报告页和赛道页共享过滤、分页、排序交互。
- 新增 `TrackModelComparison`，基于赛道结果的 `capability_blocks` 和 `capability_metrics` 比较两个模型的主指标。

## Commit Plan

每完成一个可独立验证的小功能就提交一次：

1. 文档/spec/plan。
2. 后端赛道结果摘要 API。
3. 运行列表折叠、模型三态提示。
4. 排名卡片简化。
5. 赛道能力雷达图和样本列表。
6. 模型比较入口。

## Testing

- 后端 API 测试覆盖最近成功结果选择、失败状态提示、样本聚合分页。
- 前端 Vitest 覆盖运行列表默认折叠、模型三态提示、排名策略控件消失、雷达图渲染、样本分页、模型比较高亮。
- 每个提交运行对应聚焦测试；最终运行后端和前端相关完整测试。
